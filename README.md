# Лампа

Android-приложение и виджет для потолочной лампы с тремя кольцами. Лампа — устройство **Tuya** с Wi-Fi
и Bluetooth (код продукта `d3nbkezo71wfnlqh`). Приложение управляет ею напрямую по домашней сети Wi-Fi,
без интернета и без Smart Life; по Bluetooth — только если телефон не в домашней сети.

| Где | Что умеет |
|---|---|
| **Приложение** | плитки «Ночник» и «Максимум» и все 8 кнопок пульта в том же порядке |
| **Виджет 2×1** | «Ночник» и «Максимум» в стиле кнопок жалюзи из DiWA Remote: активный режим подсвечен, повторное нажатие на него выключает свет |
| **Веб-страница** (`web/`) | запасной вариант без установки: те же кнопки в браузере с Web Bluetooth (Chrome на Android и компьютере) |

## Настройка (один раз)

Лампа слушается только телефона, который знает её секретный ключ. Ключ появляется, когда лампу добавляют
в приложение Smart Life, и читается из облака Tuya с согласия владельца.

1. Перевести лампу в режим сопряжения: трижды выключить и включить выключателем, она замигает.
2. Добавить её в **Smart Life** (найдёт сама по Bluetooth).
3. В Smart Life: Профиль → шестерёнка → Аккаунт и безопасность → **Код пользователя**.
4. На компьютере:
   ```bash
   pip install tuya-device-sharing-sdk segno
   ```
   ```bash
   python tools/tuya_key.py <код пользователя> [--mac <Bluetooth-адрес лампы>]
   ```
   Скрипт сохранит QR-код в `tools/tuya-login.png` — его нужно отсканировать приложением Smart Life.
   Появится `lamp-config.json` с ключом (в git не попадает).
5. Передать файл в приложение (телефон на USB):
   ```bash
   adb shell "run-as home.lampremote sh -c 'cat > files/config.json'" < lamp-config.json
   ```

Если лампу удалить из Smart Life и добавить заново, ключ сменится — шаги 4–5 надо повторить.
Адрес лампы в сети приложение находит само; при желании его можно вписать в `lamp-config.json`
полем `"ip"`, тогда первое нажатие не тратит секунду на поиск.

## Как это устроено

```
app/src/main/java/home/lampremote/
  WifiLink.kt      соединение по Wi-Fi: протокол Tuya 3.4 (TCP 6668), поиск лампы в сети
  Tuya.kt          протокол Tuya BLE v3: шифрование, пакеты, точки данных (без Android)
  TuyaLink.kt      соединение по Bluetooth: вход по ключу, команды, отчёты лампы
  LampLink.kt      общее у обоих соединений
  Config.kt        ключ и номера точек данных из files/config.json
  Lamp.kt          логика кнопок и время жизни соединения
  Store.kt         последнее известное состояние лампы (для виджета)
  LampWidget.kt    виджет, приёмник нажатий, короткий foreground-сервис
  MainActivity.kt  пульт
web/                   веб-страница: тот же протокол на JavaScript и кнопки
tools/
  tuya_key.py          получение ключа лампы
  web_link.py          ссылка настройки для веб-страницы
  gen_tuya_vectors.py  эталонные пакеты Bluetooth для тестов (из ha_tuya_ble)
  gen_lan_vectors.py   эталонные сообщения Wi-Fi для тестов (из tinytuya)
```

- «Ночник» = включить на минимальной яркости (1 %), «Максимум» = включить на максимальной. Остальные
  кнопки: «Ярче» / «Темнее» — шаг 10 %, «Тёплый» / «Холодный» — края шкалы, «Оттенок» — тёплый →
  нейтральный → холодный, «Таймер» — выключение через 60 секунд.
- Перед каждой командой приложение спрашивает у лампы её настоящее состояние, поэтому нажатия работают
  правильно, даже если свет меняли родным пультом, выключателем или с другого телефона. Лампа отвечает
  только на запрос с перечислением номеров точек данных; на запрос «всё» она молчит.
- Подсветка виджета между нажатиями показывает то, что лампа сообщила в последний раз; приложение
  обновляет её при открытии.
- По Wi-Fi от нажатия до команды около 0,3 секунды. Свет при включении лампа разгоняет сама, ещё
  около двух секунд. После команды соединение живёт ещё 5 секунд: следующее нажатие срабатывает сразу.
- Адрес лампы приложение запоминает. Если по нему лампа не отвечает (роутер выдал другой), приложение
  опрашивает все адреса своей сети /24 на порт 6668 и узнаёт лампу по тому, что она принимает её ключ.
  Широковещательные объявления лампы (UDP 6667) на телефон через Wi-Fi не доходят, поэтому на них
  приложение не полагается.
- Bluetooth у лампы включается только на пару минут после подачи питания, дальше она только в Wi-Fi.
  Поэтому Bluetooth — запасной путь для телефона вне домашней сети; в домашней сети лампа, которая не
  отвечает по Wi-Fi, обесточена, и приложение не тратит время на Bluetooth.
- Выключатель на стене обесточивает лампу: тогда её не включит ни приложение, ни Smart Life, ни пульт.
- Родной пульт лампы работает на собственном радиопротоколе 2,4 ГГц, телефон его не слышит — поэтому
  приложение не копирует пульт, а управляет лампой так же, как Smart Life.
- Виджет запускает короткий foreground-сервис; если Android его не разрешает, команда уходит прямо
  из приёмника нажатий, а соединение закрывается сразу.
- Протокол перенесён с открытой реализации [ha_tuya_ble](https://github.com/PlusPlus-ua/ha_tuya_ble);
  тесты сверяют пакеты с эталонными, собранными ею же.

### Виджет и сетка иконок

Кнопки виджета размером с иконку приложения, стоят ровно там, где стояли бы иконки, и скруглены так же.
Размеры сняты с лаунчера HyperOS (5 колонок, 30.09.2026) и записаны в `res/layout/lamp_widget.xml`:
ячейка 240×240 px, иконка 172 px со скруглением около 46 px, один dp виджета — 2,536 px. Виджет помечен
`miuiWidget`: тогда лаунчер отдаёт ему прямоугольник по границам иконок, без полоски под подпись. Корневой
вид объявлен фоном со своим контуром (`@android:id/background` + `clipToOutline`), иначе лаунчер сам
скругляет виджет сильнее иконок и срезает углы кнопок. При другой сетке рабочего стола числа надо перемерить
(`uiautomator dump` показывает границы виджета и иконок).

### Веб-страница

Запасной вариант, если приложения под рукой нет: страница с теми же кнопками в браузере с Web Bluetooth
(Chrome на Android и на компьютере). Адрес: <https://tie-channel.github.io/lamp/>. Она публикуется сама
при каждом изменении `web/` в ветке `main` (`.github/workflows/pages.yml`), туда попадают только
`index.html`, `app.js` и `tuya.js`.

- Ключ лампы в страницу не зашит. Его приносит одноразовая ссылка настройки:
  ```bash
  python tools/web_link.py https://tie-channel.github.io/lamp/ --qr
  ```
  Ключ идёт после `#`, на сервер не отправляется и сохраняется в браузере. Ссылку и QR-код
  (`tools/web-link.png`, в git не попадает) никому не пересылать.
- Браузер показывает список устройств только по нажатию: при первом нажатии нужно выбрать лампу (`TY`).
- Страница держит соединение 3 секунды после команды и отпускает лампу сразу при сворачивании, чтобы
  она оставалась доступной приложению и другим телефонам.
- `tuya.js` проверяется теми же эталонными пакетами, что и приложение: `node --test web/tuya.test.mjs`.
  Без лампы страницу можно проверить на компьютере: `web/fake-lamp.js` отвечает за лампу по тому же
  протоколу (как подставить — в начале файла).

## Сборка и установка

Нужны Android SDK и JDK 17 (тот же, что для DiWA Remote).

```bash
JAVA_HOME=~/.gradle/jdks/eclipse_adoptium-17-amd64-windows.2 ./gradlew testDebugUnitTest assembleDebug
```

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

На Xiaomi/Redmi во время установки на экране телефона появляется запрос «Установить через USB» —
его нужно подтвердить за 10 секунд, иначе `INSTALL_FAILED_USER_RESTRICTED`.

Там же (HyperOS) виджет не добавится, пока приложению не разрешены ярлыки: Settings → Apps → Manage apps →
Лампа → Other permissions → **Home screen shortcuts**. Без этого лаунчер молча отклоняет запрос
(`add widget failed, home.lampremote has no permission` в logcat).

Весь обмен с лампой дублируется в logcat с меткой `LAMP`:

```bash
adb logcat -s LAMP:V
```

В отладочной сборке кнопки можно нажимать с компьютера (`dim`, `bright`, `press:POWER`, `press:NIGHT`,
`press:BR_UP`, `press:BR_DOWN`, `press:CCT`, `press:COLD`, `press:WARM`, `press:TIMER`):

```bash
adb shell am broadcast -n home.lampremote/.LampActionReceiver --es action dim
```
